# Local Docs

- GitHub repository webhooks (verified 2026-07-25): repository hooks can subscribe to both `push` and `pull_request`; PR preview lifecycle should react to opened/reopened/synchronize and closed deliveries. Context7: `/websites/github_en_rest`.
- Azure DevOps Service Hooks and PR statuses (API 7.1, verified 2026-07-25): use `git.pullrequest.created` plus `git.pullrequest.updated`; payloads expose `pullRequestId`, `status`, `sourceRefName`, `lastMergeSourceCommit.commitId`, and repository/project coordinates. Publish preview links with `POST .../pullRequests/{id}/statuses?api-version=7.1`; posting the same `context.genre` + `context.name` updates that logical status. Context7: `/microsoftdocs/azure-devops-docs`, `/websites/learn_microsoft_en-us_rest_api_azure_devops`.
- Cloudflare DNS API v4 (verified 2026-07-26): use scoped bearer API tokens; resolve the exact zone before mutating records; A/AAAA records cannot coexist with CNAME at one name, so reconciliation must report conflicts rather than delete foreign records. Context7: `/websites/developers_cloudflare_api`, `/cloudflare/cloudflare-typescript`.
- Docker/OCI distribution (verified 2026-07-26): authenticate to the target registry, push immutable commit-tagged images, record the returned digest, and deploy by digest. Registry-backed BuildKit cache is the portable cache path for later worker isolation. Context7: `/docker/docs`.
- OCI Distribution token authentication (verified 2026-07-28): a registry may correctly return `401` plus `WWW-Authenticate: Bearer realm=...,service=...,scope=...`; clients must request a token from that realm with the supplied service/scope and Basic credentials, then retry the registry request with the returned Bearer token. Do not treat the initial challenge as invalid credentials. Context7: `/distribution/distribution`.
- Kubernetes 1.31+ deployment provider (verified 2026-07-28): generate `apps/v1` Deployments plus stable Services, use immutable image references, `RollingUpdate` with explicit surge/unavailable limits, and server-side apply under a dedicated `openship` field manager. Gate success on `kubectl rollout status` with a bounded timeout. OpenShip owns only resources carrying its managed/project labels. Context7: `/kubernetes/website`.
- Kubernetes stack operations (verified 2026-07-29): spread replicated workloads across `kubernetes.io/hostname`, use `policy/v1` PodDisruptionBudgets with `maxUnavailable: 1` so later scaling remains safe, and scope every scale/restart/pod-replacement action to resources bearing the OpenShip project label. Never expose raw `kubectl` input through the API. Context7: `/kubernetes/website/snapshot-final-v1.31`.
- kubectl owned-resource lookup (verified 2026-07-29): `kubectl get` accepts either a resource name or `-l`, not `resource/name` plus selectors. To preserve OpenShip's ownership label guard while targeting one object, combine `-l openship.io/project-id=...` with `--field-selector metadata.name=...`; `metadata.name` and `metadata.namespace` are universally supported field selectors. Context7: `/kubernetes/website`.
- Kubernetes stack cold starts on constrained nodes (verified 2026-07-29): apply shared resources first, then apply and await each Deployment sequentially. Applying all Deployments together can overwhelm a node's image-pull and snapshot-extraction I/O, causing kubelet CRI deadlines and abandoned sandbox-name reservations even when Kubernetes resources are otherwise valid. Context7: `/kubernetes/website/snapshot-final-v1.31`.
- Kubernetes stack completion (verified 2026-07-31): `kubectl rollout status` for every requested Deployment is the deployment success criterion. A stack without an exposed Service is valid (for example database-only/internal workloads); absence of a NodePort must not turn a completed rollout into `failed`. `service.exposed` selects NodePort versus ClusterIP, while an empty public-endpoint list means no domain route.
- Kubernetes workload health (verified 2026-07-31): a namespace is healthy only when it has at least one desired replica, all desired replicas are ready, and every observed pod is ready. A Deployment scaled to zero is a stopped/degraded workload, not a healthy one, even though its desired and ready counts both equal zero.
- SSH executor leases (verified 2026-07-29): `withExecutor` callbacks may legitimately exceed the five-minute cached-connection idle TTL (for example staged Kubernetes rollouts). Retain the connection for the entire callback, release before a retryable reconnect, and restart idle expiry only after the callback finishes.
- Bun global installs (verified 2026-07-28): Bun stores global package dependencies in its global `package.json` under `BUN_INSTALL_GLOBAL_DIR`, `$BUN_INSTALL/install/global`, or the home/XDG `.bun/install/global` fallback. A local `.tgz` is recorded as a path dependency, so update bundles must live at a durable path; never install a fork release from a temporary tarball that is deleted afterward. Context7: `/oven-sh/bun`.
- GitHub Actions cache (actions/cache v5, verified 2026-07-31): `actions/cache/restore` restores a matching cache without the combined action's post-job save phase. Use it for release-critical jobs when cache-save cleanup could delay publication; use an explicit `actions/cache/save` only where cache warming is worth the extra job phase. Context7: `/actions/cache`.
- GitHub Actions conditional jobs (verified 2026-07-31): workflow-level `env` is documented for step conditions but is not available while GitHub evaluates a job-level `if`; use a literal `${{ false }}` temporary gate (with a restoration comment) or a repository `vars` value for optional job groups. Context7: `/websites/github_en_actions`.
- PGlite live backup (verified 2026-07-28): call the active client's `dumpDataDir("gzip")` to create a consistent compressed data-directory archive without opening the same directory from a second process. Restore that artifact only through PGlite's `loadDataDir`; compatibility with other PostgreSQL versions is not guaranteed. Context7: `/electric-sql/pglite`.
- PGlite offline repair (0.3.15, verified 2026-07-29): after fully stopping the owning process and taking a data-directory backup, `new PGlite("/absolute/data/dir")` opens an existing filesystem-backed cluster in Bun/Node; execute additive SQL with `query`/`exec` and always `close()` before restarting the service. Never open the same data directory from two processes. Context7: `/electric-sql/pglite`.
- Supabase PostgreSQL image (verified 2026-07-31): mount the custom `99-roles.sql` at `/docker-entrypoint-initdb.d/init-scripts/99-roles.sql`, not the root initdb directory. The image processes `init-scripts` after it creates its internal roles; a root mount runs too early and fails clean-volume installs with `role ... does not exist`. Role sets also differ by image release, so iterate over known role names and conditionally alter only roles that exist; an `ON_ERROR_STOP` failure otherwise skips later Auth-function ownership fixes. Official Compose reference: `https://github.com/supabase/supabase/blob/master/docker/docker-compose.yml`.
